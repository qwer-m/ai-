# Agent 记忆与缓存边界调整

## 已完成的变化

来源事实、已验收产物和失败诊断具有不同用途。候选只有通过当前版本的完整验收才能推进正式领域状态或成为成功产物；被拒内容保留用于反馈和审计，不成为新的事实源，也不能按成功结果命中缓存。多次判断产生的诊断记录不等同于可复用的权威记忆。

- 缓存身份自动覆盖真实 Agent/子 Agent 定义、工具、Schema、模型路由、输入投影、节点契约、相关源码及 SDK/文档渲染依赖。删除内置缓存的人工版本与旧格式放行配置。
- 每次 SDK 构建保留实际使用的定义和工具快照，以实际客户端计算调用指纹。映射项实际契约与节点开始时契约不一致时，结果不进入缓存，防止任务执行期间修改配置造成身份错记。
- 成功结果保留后处理前的结构化输出。历史复用需在独立只读事务内重跑 Schema 和完整业务后处理，并与持久结果完整比较。无新指纹或复验依据的历史结果不复用。
- 缓存候选损坏会记录拒绝原因；当前任务自身输入快照损坏仍直接拒绝执行。
- 删除旧候选强制恢复函数及 protected_* 修补协议。差异目标只表示已经发现的问题，模型的新输出整体接受当前校验，未被指出的内容不再被强制恢复为旧值。
- 节点输入按完整内容摘要引用同一运行较早成功节点的输出；引用记录包含来源节点、路径、局部摘要和完整输入摘要。API 与运行时还原完整输入。
- 续跑先还原父节点输入，再在新运行内重建引用。运行汇总不再重复保存 run_context.artifacts，对外序列化保持完整。
- 续跑注册指纹、结果缓存和持久行动身份统一复用完整源码摘要。删除仅检查公开处理器函数体和人工列举执行策略模块的重复哈希逻辑，私有辅助函数的源文件变化也使旧执行契约失效；不改旧检查点摘要绕过版本检查。
- 专家咨询不再要求模型转抄完整来源 JSON。平台固定传入同批真实投影，并以完整原始输入验收专家输出；咨询问题不能覆盖事实、编号或预算。正式 Run 31 已自然触发咨询并通过最终验收。

## 生效范围

没有新增数据库表，也没有迁移或改写历史运行。紧凑输入用于后续新写入，旧完整输入仍可读取。既有缓存缺少新的自动身份与原始复验依据，因此会重新执行模型生成。

上述缓存专项当时没有重启服务或运行新的模型生成任务。后续已由加载当前代码的新 Worker 进程创建正式 Run 29–31，结果见[自主性演进报告](2026-09-20-agent-autonomy-roadmap.md)；既有常驻服务尚未重启。后端与 Worker 需加载同一份更新代码。缓存专项只证明存取、复验、修补和恢复边界，不代表语义错误能够全部由程序识别。
