# 冗余收敛与真实数据验证

日期：2026-09-17。

## 修改结果

- 项目归属查询从六个数据访问类收敛到 system_components 的 ProjectRepository。四个业务服务直接使用它并共享请求原有的 Session；删除知识库重复仓储和无业务语义的转发函数。
- Android 检测与执行共用设备选择、前台应用识别。统一读取 ADB_PATH，显式指定设备也必须在线；无设备、多设备未指定时给出中文失败原因。保留先读取窗口焦点、再读取应用焦点的优先级。
- 前端错误提取和翻译统一到 utils/api.ts，保留 APIError 已解析的 message，删除评估和接口测试中的重复实现并迁移调用方。
- Agent 列表、详情、评估创建响应复用同一请求与严格解析契约。评估页面保留业务产物投影，删除重复 DTO、状态枚举及请求函数。
- 复核发现评估摘要的生产输出上限为 1000 字，旧需求基线声明和前端校验却限制为 500 字。后端三处摘要声明现在复用同一契约，前端对齐 1000 字，并按 Unicode 字符计数，避免合法报告阻断历史列表。
- 删除 11 个确定失效的样式声明。保留有效主题、响应式规则与阴影，没有增加样式版本层。

## 验证边界

- 当前未连接 Android 设备，未执行真机成功路径、多设备选择或前台应用识别验证。
- 数据库没有同时包含公开文档与内部产物的项目，内部产物筛除测试明确跳过。
- 现有六条运行记录没有 test_evaluation 产物，质量评估产物投影没有真实样本覆盖；既有质量报告严格校验仍保留。
- 本机 Redis 连接超时，缓存组件启用已有本地缓存路径；本轮不包含 Redis、Worker 或模型执行验收。
- CSS 验证基于真实源码的级联规则，未进行浏览器视觉回归。
