# 首批重构实施记录

本批针对 API 重复消费、缓存失效、生成前重复编排和费用证据丢失进行修改。全程没有新建/重跑模型任务、没有调用付费模型、没有充值或给用户配置消费授权。保留原有工作区修改，没有重置仓库。

## 已实施

1. **实际请求前累计准入。** 新增用户、项目、逻辑任务的独立消费账户与请求流水；按明确配置的模型价格预留，缺价格或额度就拒绝出网。跨重试累计，不靠重置显示次数或新 Run 刷新用户/项目消费。项目/任务默认继承用户上限，显式设置后独立限制；调高额度不清零已消费或未知预留。
2. **请求身份和费用事实独立持久化。** 每份预留只允许一次同服务、同模型的发送，发送状态写库防重复；Agent 发送前再次核对 claim 与租约。收到实际 usage 后幂等结算，缓存/推理缺失保持 unknown；已发送但结果未知时保留预留，确定未发送时释放预留。超出预留的实际费用照实记录，并停止同计价版本的后续请求。晚到的真实响应仍可补全同一请求的实际用量，不恢复已取消的业务执行。
3. **模型入口统一计量。** SDK 在原始响应被转换前保存 usage；OpenAI 兼容非流式、流式和原生 DashScope 请求接入相同门禁。删除空响应再发流式请求、400 后偷偷移除参数重发、文本连接失败再换另一接口等隐藏消费路径。DashScope 凭据改为每次调用传入，构造另一个客户端不再覆盖全局密钥。
4. **证据不再随终态自动删除。** 移除终态物理清理主体及无效的历史删除配置，列表展示条数不再等于删除运行、节点、事件和审批。已删除的旧历史没有假恢复或伪造费用回填。
5. **缓存边界收敛。** 失败父 Run 的成功纯节点可进入候选；通过可信 cache_safe 处理器声明、租户/来源/完整输入/当前验收防止副作用重放。产物语义身份按实际源码传递依赖计算，Run 构建冻结仍保留；思考参数纳入实际模型身份。旧全局哈希不自动改写为新缓存命中。
6. **来源治理前置。** 工作流先提取事实，再独立治理完整来源，之后才初始草案和规划。治理不再由易变的测试模块决定，也不因没命中有限关键词就跳过纯文本治理。保留断言、出处、上下文和治理关系；删除旧后置重复裁决。
7. **容量与收费计量分开。** 支持复核按冻结专家容量估计分批，删除固定每 3 个意图一片。收费预留采用保守文本上界；容量预测单独使用估算，避免收费上界收紧把规划切得更碎。收费图片需显式配置已核实的单图计费 Token 上界，未配置不发送收费图片请求，不对任意模型假定一个通用图片上界。
8. **无进展停止。** 同一领域版本重复已否决参数、重复违反相同合法行动约束、相同无变化工具结果或相同候选/错误时停止；输入、证据或版本真实变化仍可继续。普通正文最多获得一次协议纠正，再次没有有效工具进展就停止。此错误不触发整节点反复重试。
9. **稳定初始请求前缀。** 系统协议和首条任务输入固定，当前状态和共享预算放在尾部。注册工具协议保持稳定，执行入口按当前状态校验合法范围；历史快照仍按有效性处理，因此不承诺整个历史串永远不变或厂商必命中。
10. **配置验证停止隐性付费。** 删除五档自动探测，只验证实际选择；验证成功不再自动发流式测试。保存依赖绑定用户、端点、模型、协议和凭据的短期签名证据，不重复请求模型。签名从部署加密密钥按用途派生，不能用公开开发默认 JWT 密钥伪造。
11. **消费配置界面和查询。** 配置中心新增累计额度、用户核实的每百万 Token 价格及可选图片上界；没有默认价格，不自动开放额度。金额按配置价格计算，未知缓存保守处理，不冒充供应商最终账单。提供独立请求流水读取接口。
12. **同事务投递意图。** pending 与 outbox 一起提交；broker 回执丢失重用稳定 task_id，重投有间隔、发布租约和次数上限；新周期拒绝旧消息。恢复只扫描明确意图，不启动 dispatch=False 或旧无意图历史任务。
13. **上下文和尝试身份。** user/project scope 绑定真实 owner，普通用户不发布全局共享知识；显示次数用独立偏移，不修改真实 attempt_id，分支重试取逻辑任务最大真实序号加一。执行契约升级 v4 并冻结实际思考档位，旧契约明确拒绝继续。
14. **缩小状态轮询。** 每秒状态查询仅取 status，不再读取整个 Run 大 JSON；未把全部检查点拆表或引入永久双写。

## 数据库与本地服务

已实际创建并回读以下四张空表：`model_spend_accounts`、`model_price_versions`、`model_request_records`、`agent_run_dispatches`。迁移脚本分别为 `create_model_spend_ledger.py` 与 `create_agent_run_dispatches.py`，后者不回填/重投任何旧任务。

真实账本正反例在 MySQL 外层事务与 savepoint 中重放，最后回滚；配置和费用行数回读均为 0。自增序号可能留下事务回滚产生的间隙，不影响费用或身份唯一性。没有给用户设置测试价格或累计上限。

开发前端与后端 HTTP 回读均为 200，后端 OpenAPI 已包含新消费接口。Worker 在空闲且没有保留任务时正常重启加载修改；没有发送生成任务。

## 未完成与验收边界

- 没有再跑真实模型生成，**未证明本批能将这份 CRM 文档的 50 条用例完整审查后落库**。新的全来源单次治理、容量分批和思考/工具组合仍需将来在明确小额累计预算下验证。
- 全局模块目录的稳定 ID 与增量依赖拆分尚未实施。真全局依赖不能通过放宽输入 hash 冒充局部缓存；局部草案变化仍可能引发较大范围重算。
- 单个子结果和领域聚合仍存在两级完成口径；费用流水已独立，但技术预算、完整领域和部分历史回执仍在大 checkpoint 中，尚未完成瘦身。
- 全局准确交付预算的自动预分配尚未实施，现有实例技术额度继续生效；不会自动扩大额度来维持运行。
- 历史本地/UTC 混存与独立成果版本生命周期尚待单独迁移，不能对全部历史时间机械加减 8 小时。
- 动态需要审批的工具目前显式拒绝绑定，保留已有审批工具节点；没有假装已完成 SDK 动态审批映射。
- 成本上限依赖用户核实的币种、价格和图片上界；不是供应商余额或最终账单的自动同步。未知历史费用不补成 0，账户也不会自动解锁发请求。
