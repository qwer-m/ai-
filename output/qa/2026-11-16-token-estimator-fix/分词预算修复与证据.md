# 分词预算修复与证据

本次只做 CPU 分词、已保存真实用量和共享账本回归，不调用模型、不写业务数据库，不修改 Run64/65。完整生成的实际用量仍须以新 Run 服务商回执验收。

原准入将完整 SDK JSON 的 UTF-8 字节数当作 token，再加 8192 固定文本余量；在真实中文来源和工具协议上明显多预留。新准入使用 tiktoken BPE，对本地可见的指令、输入、工具 schema 和输出 schema 分词，再加 15%（至少 256 token）协议余量。图片编码单独移除，不对 Base64 逐字计费；尚未验证的模型图像编码声明为每张 4096 token 的近似预留，本轮无图时不产生图像预留。

`gpt-6.1-terra` / `gpt-6.1-sol` 不在当前 tiktoken 0.14.0 官方映射中。API 和 Worker 必须同时显式配置 `AGENT_TOKEN_ENCODING_MAP={"gpt-6.1-terra":"o200k_base","gpt-6.1-sol":"o200k_base"}`。这是代理别名的可审计近似，不能声称官方精确映射。未知且未配置的模型在发送前拒绝，不暗用默认编码。

| 真实内容的 CPU 投影 | 旧字节规则预留 | 新 BPE 文本数 | 协议余量 | 新预留 |
| --- | ---: | ---: | ---: | ---: |
| Run65 冻结主 Agent 协议、工具定义及已有来源目录 | 72,203 | 21,693 | 3,254 | 24,947 |
| 同一真实来源的正文文字 | 29,951 | 6,670 | 1,001 | 7,671 |

这些是对保存内容重新组装的 CPU 投影，**不是原始 SDK 请求**。历史没有保存完整 SDK 输入，因此没有填造“新估计对原始回执误差”。Run65 的 7 个已报告响应输入 116,870、输出 7,770、合计 124,640 token；另有 1 个 504 未知请求，原预留输入 77,011、输出 10,000。旧未知预留没有按新公式追溯退款，也没有清零。新请求只使用新估计，成功响应仍按实际回执结算。

新预算 snapshot 的可选 `input_estimator[model]` 保存模型名、编码、映射来源、分词库版本、文本分词数、协议余量及图像近似依据。历史 snapshot 没有此字段时保持缺省，不能伪填历史依据；它与 `reported_usage` 明确分开。

`test_token_estimator_real_data.py` 与 `test_shared_budget_concurrency_real_data.py` 合计 13 项通过：真实正文和协议分词、显式未知别名、SDK 模型对象、历史未知费用保留、恢复元数据、父子共享预算、并发等待及失租/取消防护。运行命令和结果见同目录 `cpu-token-estimate.json`。

依据：[tiktoken 官方模型映射](https://github.com/openai/tiktoken/blob/main/tiktoken/model.py)、[OpenAI 输入计数说明](https://developers.openai.com/api/docs/guides/token-counting)、[官方本地计数示例](https://cookbook.openai.com/examples/how_to_count_tokens_with_tiktoken)。文本 BPE 计数不等于全部协议精确计数；实际回执才是收费事实。
