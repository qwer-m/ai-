# Agent 运行清理与来源表格修复

## 已执行的清理

经用户明确选择，删除全部 Agent 运行及执行记录，保留旧 Run 55 的输入，以相同输入创建全新的 Run 1。

- 删除 25 条 `agent_runs`、556 条 `agent_node_runs`、6,154 条 `agent_run_events`；审批记录原本为 0。
- 按实际外键依赖顺序执行事务删除；4 张运行表的自增编号均重置为 1。
- 清理前确认全部运行已终止，Celery 没有活动、待执行或定时任务。
- 原始需求文档与业务数据未修改；旧失败输入保存在本目录的 `2026-10-12-run55-reset-source.json`，用于真实回归和复用运行参数。

## 根因与修改

1. PDF 保留了超出页面范围的绘图路径，表格识别将跨页外框当作巨型单元格，混合正文、业务表格和批注。现在拒绝边界超出当前页面的表格候选，不裁剪外框制造行列关系。使用页面几何数据判断，不包含文档名、页码或业务文字特例。
2. 同一文本块可横跨表格多列。现在为当前输入中的单元格片段提供 `source_span`，由已有的原文与局部坐标映射产生；仅供上下文的片段不提供可引用坐标。
3. 在模型坐标转换前校验表格示例值。错误反馈提供事实 ID、所选单元格、当前输入坐标、允许范围及同行实际文字，继续拒绝跨列引用。
4. 文本和视觉来源 Agent 共用的说明明确要求选择规则正文所在单元格，禁止仅按文本块 ID 选第一列。
