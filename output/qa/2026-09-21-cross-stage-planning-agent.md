# 同源取证与跨阶段重规划

日期：2026-09-21，2026-09-23 续更。本文记录本轮实现与验证；上一轮 Run 31 的完整交付属于历史基线。

2026-09-23 后续演进已继续实现：下文的独立规划/终审协调器和 24 节点图现在作为历史阶段保留。当前统一目标协调者、14 节点图、真实数据回放及后续模型验证见[统一生成闭环](2026-09-23-unified-generation-agent.md)。

## 问题与本轮范围

真实 Run 31 的初始草案把“审批列表展示字段”推导成“提交时采集和传递字段”。路由缺口复核判定相关覆盖意图没有依据。旧流程删除覆盖项后仍保留错误的模块、测试点目标，并继续传给生成阶段。详见[原始链路证据](2026-09-21-cross-stage-real-origin-evidence.md)。

本轮把生成之前的规划、路由、缺口复核合并为持久 `resolve_planning` 节点。协调 Agent 根据当前事实、草案、路由差异选择行动，能够回查原文、重新分析来源、修订草案，再重建计划。最终产物同时提供当前完整来源语义和通过验收的规划，下游权威协调和生成使用这一版本。

外层 DAG 仍负责来源获取、初始并行分析、阶段依赖和落库。本轮不支持重写已完成的任意 DAG 节点，也不宣称整个系统已经完成强 Agent 演化。

## 行动与验收边界

| 行动 | 实际数据与职责 |
|---|---|
| `read_planning_evidence` | 按当前 Run 原始目录的证据 ID 分页读取完整原文，保存内容摘要和已读区间 |
| `reinspect_planning_source` | 使用原始准备输入和原有文本、视觉专业 Agent 重新分析选定来源项 |
| `revise_planning_draft` | 使用当前事实和原有草案专业 Agent 修订一批完整草案，连同目标、覆盖意图、风险一起修正 |
| `rebuild_business_plan` | 补齐因来源变化而失效的草案，再按当前完整覆盖目录重建计划 |
| `route_planning_scopes` | 对当前待路由输入调用原有路由专业 Agent |
| `review_planning_route_gaps` | 对当前尚未复核的缺口进行独立语义判断 |
| `finish_planning` | 校验当前来源、草案、覆盖目录、完整规划与全部路由；存在无依据意图时拒绝完成 |

来源、草案、规划分别维护版本。来源重新分析替换对应完整记录，并重新合并事实；不会把新旧解释直接追加在一起。草案仅在完整准备输入摘要相同时复用。批次位置和数量也是输入的一部分。

路由输入目前包含整个模块目录，因此模块结构变化可能使全部路由失效。不能将其描述为任何情况下都只重跑一个模块。

模型的问题文本、历史候选和失败反馈都不是新增业务事实，也不能改变来源权限、真实来源版本和预算。新协调节点的父子调用共用 64 次 SDK 请求上限，属于比旧规划节点更大的职责范围；不能直接与旧 Planner 的 6 次额度作等量成本比较。最初 40 次的专项失败记录保持原状，没有补充预算续跑。

## 当前实现的限制

来源重新分析复用原始准备项，可纠正该项所包含范围的遗漏或误解；尚不支持任意扩大先前压缩选区之外的视觉范围。原始页面和坐标映射都必须与当前 Run 持久来源一致。

行动日志以父行动整体提交为恢复边界。一个批量行动未提交就中断时，其已完成的专业子调用可能重做；本轮没有实现逐子调用持久化。

本轮不包含任意外部检索、跨项目记忆学习、在线权威冲突回退至生成后阶段，或任意 DAG 回卷。独立模型判断也可能误判；结构和引用检查通过不等于全部业务语义正确。
