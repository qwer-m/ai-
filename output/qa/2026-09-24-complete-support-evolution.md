# 完整意图支持与定向反馈演进

更新日期：2026-09-24。当前实现已完成源头支持关系、生成承接、修复派生及最终支持校验的修改；真实模型主流程仍在验收。当前 14 节点图尚无成功的正式交付记录，不能将旧图成功、局部专家成功或数据回放解释为全部演进完成。

## 源头修正

旧关系表示事实与设计项“相关”，下游却把命中其中任意事实当成覆盖了整个设计意图。当前在规划阶段独立复核全部设计项，保存每项完整支持事实集合及实际审查输入摘要。既有关系仅作为审查输入，不再自动成为支持结论。真实历史 21 个批次中，40 条用例存在会被新集合算法拒绝的局部支持声明；这说明算法边界修正有效，不代表这些旧关系已经过新版语义审查。

生成布局区分每批必须承担的事实和可引用的支持上下文。每个设计项只归属一个生成批次，完整支持事实可以作为其他批次的上下文；所有事实义务、设计项归属和用户总用例预算继续完整验收。用例必须实际绑定完整支持集合，平台才派生该设计项编号。修复不能直接改写编号；最终交付前按模块再次检查完整支持，允许同模块内的合法内容迁移。

全部支持审查完成后，协调者仍可用具体问题及设计项选择定向复核已有结论。历史审查回执保留，新结论须有真实输入及来源身份；支持版本变化会使依赖它的规划、权威、生成和审查失效。没有用“再次抽取直到通过”代替问题定位。

## 真实反馈问题与修正

`full-support-resumed3` 诊断完成 16 个模块、173 个设计项的初审，其中 1 项为 unsupported，但同条理由明确写出原文可直接支持且“应支持”。协调者确实注意到了矛盾，却用空选择器申请复核，被旧提示拒绝后，转而把全部审查反馈传播到多个草案，出现重复改写和无变化动作。

该隔离诊断通过真实生命周期取消，在线 Run 38 未改动。取消后在途子调用受到租约边界拒绝；该次终态是诊断取消后的 RunLeaseLost，不是网关错误。

修正复用现有观察和准备函数：只投影未解决项；草案修订仅接收其真实来源批次相关的问题；空选择器反馈列出可复核目标及必填参数；规划动作回执仅保留版本变化、changed 和下游失效信息，完整当前状态由观察器提供。原始日志和审查回执不删改。

[真实回执回放](../../backend/artifacts/verification/run38_planning_support_feedback_scope.json)按当前契约重新验证 1 份规划、25 份路由、16 份支持审查，共 42 份真实子调用。未解决项仍为原来的 1 项。原始草案请求 JSON 从 140,598 字节降为 9,783 字节；这是该条输入的变化，不是 HTTP 线包、Token 或全运行费用降幅。

## 网关定位和恢复记忆修正

`focused-feedback-resumed2` 新增 19 次成功响应后，第 20 次路由请求在 5.108 秒失败，上下文 32,595 SDK 序列化字节。`focused-feedback-resumed3` 新增 18 次成功响应后，第 19 次路由请求在 4.776 秒失败，上下文 33,476 字节。两次均为 HTTP 500，脱敏正文明确为 `Database error, please contact the administrator`，类型 `new_api_error`。这是模型网关返回的错误；未据此推断网关内部哪个数据库或 SQL 出错。没有复现 504 或超长 JSON 处理不完。

累计账本为 47 次尝试、43 次响应、4 次 interrupted、pending=0；实际已报告输入 494,237、输出 26,948 Token。保守已收费预留分别为 690,278/46,948，不等同于实际已报告用量。原始报告、SQLite 和在线 Run 38 状态保持不变。

恢复行为另外暴露平台可修正的问题：旧 `recent_action_errors` 仅传错误文本，没有失败工具及参数，且将恢复开始时的错误反复固定注入后续观察。协调者在路由未完成时重新取证和重建，规划版本增至 3；输入变化使前轮有效子回执无法命中，不应把它解释为缓存损坏。

当前复用行动日志投影失败工具、原参数、与当前状态的关系，以及该次行动已保存的专业子调用数量。每次请求读取当前日志，相同参数后续成功的旧失败不再列为当前待处理失败；原始回执不修改，也不自动执行失败工具。协调者提示区分服务中断与业务缺陷。

[真实恢复投影验证](../../backend/artifacts/verification/run38_action_failure_projection_real_data.json)覆盖本次路由失败、实际早期支持复核失败后同参数成功的历史，以及当前 SDK 输入过滤器。未调用模型、未改原状态和数据库，16 项契约检查通过。修正后父协调者的自然恢复行为仍须新模型验证。

最终模块支持校验也修正了一个新契约的边界：单批派生本批负责的设计项，共享上下文可能额外支持别批设计，终审不应强迫它补填这些额外编号。当前要求每个实际声明均有完整支持且模块所有意图都有有效声明，缺失和无依据声明仍拒绝。

[真实模块生成](2026-09-24-complete-support-generated-module-real-model.json)共获得 8 次模型响应，2 批、3 条候选均通过原始逐批生成契约；诊断脚本随后错误地直接连接批内编号，导致 `TC-001` 重复。此错误属于 QA 合并方式，未发生平台交付。修正脚本以复用正式 `merge_grounded_generation_batches` 后，对原来的两份模型原始输出重新执行当前完整契约，不再调用模型，[复验通过](../../backend/artifacts/verification/run38_complete_support_generated_module_real_data.json)。真实 TC-001 确实完整支持额外的 TD-003-002-001，验证了旧终审等值检查会误拒绝；新版通过且删除必需声明的负向校验仍拒绝。该结果只覆盖当前支持规划的模块组件，未经重新权威协调、独立语义终审或正式交付。

包含恢复记忆修正的完整协调诊断已从原始真实来源开始，证据为 `2026-09-24-action-aware-recovery-original-real-model.*`；它是新执行身份的独立诊断，不是把旧运行跨代码版本恢复或将旧消费退款。

## 权威判断后的支持缺口

上述诊断首次在第 14 次请求遇到相同远端 HTTP 500。相同身份恢复后，协调者读取目录并继续原路由，没有重建规划；复验复用了已完成子调用，规划版本一直为 1，18 份路由和 12 个模块的全部支持审查完成，随后自然接受规划并调用 11 组权威协调。

权威专家把 DOC278-P0005-F15 标为 reference_only：它是带样例金额和具体按钮状态的分期欠款截图实例，而 DOC278-P0003-33 已提供“先补齐分期欠费、不能续约”的规范规则。该判断导致一个完整支持集合部分失效。旧准备函数只返回 TD-011-004-008，父权威行动整体回滚；协调者随后猜成模块索引 11、意图索引 4，并问了不相关的“已通过的续费审批详情”。这是真实数据流缺口，不能解释为模型已经正确重规划。

该隔离副本通过生命周期取消，在线 Run 38 未修改。原副本最终共记录 58 次模型响应、59 次尝试，输入 505,591、输出 26,224 Token，pending=0；取消边界使终态呈现 ModelBehaviorError，不能当作新的网关故障。

当前准备函数一次返回全部失效支持及准确的原规划模块/意图索引。权威行动保留已经验收的 11 份结果，原问题流增加准备阶段问题，携带真实权威事实、判断理由和已排除事实目录；问题依赖完整规划、权威和布局身份，上游变化后旧问题退出当前观察。布局还没形成时不提供布局修改工具。定向支持复核继承当前问题，平台拒绝再次引用已排除事实，原文仍保留供取证。

[真实回放](../../backend/artifacts/verification/run38_authority_support_feedback_real_data.json)重验 42 份原始模型回执，准确定位为模块 10、意图 21：“验证有分期未缴欠费时，提示先补齐分期欠费，不能续约。”失效支持是 DOC278-P0005-F15，剩余支持为 DOC278-P0003-33。权威结果保留、旧支持拒绝和上游失效后的问题清理通过，16 项契约检查再次通过。

`2026-09-24-authority-support-feedback-real-model.*` 从这个经过当前契约重验的真实缺口继续。它建立新执行身份，保留原 59 次尝试和全部实际消费；没有重绑旧身份、重置额度、自动选择下一行动或注入预设的新专家结论。完整正式交付仍未验收通过。
