# CRM Run 39 失败修复与验收

验证对象：项目 9（CRM），文档 280，《门店运营工作台 产品需求文档（PRD）》，原失败运行 Run 39。

当前状态：正式 Run 42 在预警模块生成阶段失败，领域状态保存 12/22 批、29 条候选用例，未终审或正式交付；另外一批已验收专家回执保留在检查点中。已修复本轮暴露的支持差额反馈缺失与 SDK 包装局部预算异常两个问题。真实失败候选回放仍全部拒绝，定向模型修复 1 次响应通过原提交契约，核心回归 16 项通过（4.75 秒）。当前正从 Run 42 检查点副本执行真实模型延续验证，保留原 97 次请求和 Token 消耗；线上 Run 42 仍保持失败，不能把隔离验证当成正式全流程成功。

## 已修复的代码链路

1. **支持判断丢失依据**：专业模型输出支持事实及结构化 `support_gaps`，平台据此派生支持状态。缺口必须引用原覆盖意图片段；来源冲突引用承载冲突内容的真实候选事实，同一事实的原表上下文包含冲突双方时也可以报告。部分支持事实和冲突证据可保留给协调者，但不能进入已批准的完整支持集合。
2. **无效重分组循环**：草案和路由已完成、仅存在支持缺口时，观察和执行入口均拒绝重建规划。协调者仍可读原文、重检来源、修订草案或定向复核；实际生成、审查问题仍允许回到规划阶段。
3. **定向复核缺少上下文**：复核可从当前来源补充有效 `scope_id`，完整可信输入保留真实上一条结论供回执重验。补充范围先规范排序；反馈保留新增事实原文。历史回执按时间顺序重验，重复问题不会因上一条结论或路由标签变化而成为新的抽样请求。
4. **表格跨片丢列义**：读取同一 PDF 的真实多列网格，将单元格关联到已有文本坐标。文本按行边界分片，携带原表首行和当前行作为上下文，上下文计入分片预算。上下文不会扩大事实引用范围；规则不依赖本文档名称或业务字段。
5. **失败节点用量漏记**：自主预算检查点与 Run 汇总在同一事务增量入账，失败、恢复和重复保存均沿同一游标计算；新 Run 只记录新增消耗，继承的历史消耗仍占用原预算。
6. **事实摘要替代原表限定**：平台按已验收来源锚点派生 `source_context`，保留选中单元格的完整同行和对应列头，不改模型断言或状态、不扩大主锚点作用域、不新增事实 ID。该字段流通到规划、支持复核、生成、终审和修复；条件问题报告可以引用同一事实上下文中的一个真实单元格，不能跨单元格拼串。原先“assertion 是唯一事实文本”的约束已删除。Run 41 证明此前只留所选列与行标签会丢失同一行必要的判定方式，已在原有上下文派生函数修正裁剪。
7. **推理与工具调用协议冲突**：SDK 支持显式配置工具选择方式，使用 `auto` 时仍须通过平台的提交工具验收才能结束。请求诊断记录实际工具选择、推理开关及强度，响应记录推理项数量。真实验证证明推理请求可以到达模型，但当前路由连续用尽单响应 8,000 Token 而未提交，因此正式配置保留非推理模式和原输出限额，不能把“启用推理”当作修复成功。
8. **生成后不能返回来源**：来源重审不再以“历史上曾生成过”为禁用条件。来源发生实际变化时仍沿原有版本机制使下游产物失效；生成请求去重历史和预算账本保留。
9. **托管专家绕过输入投影**：托管调用复用节点已有的投影逻辑；模型接收业务视图，提交契约和调用身份仍绑定完整可信输入。精确单元格上下文逐条贴近对应事实传给模型；已删除没有去重收益的共享上下文目录，减少原文与候选摘要之间的间接引用。
10. **旧路由标签污染独立判断**：协调者和完整回执保留历史；支持复核的模型视图排除旧路由绑定和旧裁决，保留当前问题、来源候选及权威失效约束。输入隔离后的真实对照已完成：支持事实从原先 1 条增为 10 条，未再以旧引用关系否决；但仍发生要求高层概括与界面标签逐字一致的误拒，且该次原始输出含重复键。因此保留历史结果，不将局部改善计为语义通过。
11. **同一行多个规则共用模糊锚点**：表格事实必须显式选择真实 `table_cell`；平台校验其与原始 `block_id`、来源范围及实际网格的关系，并派生逐段 `source_segments`。跨行单元格不伪造连续引用；主锚点仍只指向所选格，同行上下文则分别保留各格及对应表头的真实坐标。普通文本和图片仍沿各自真实来源路径。旧表格候选缺少单元格定位时直接拒绝，不通过后处理猜测或补写。
12. **重复 JSON 字段静默覆盖**：模型实际曾在同一缺口中先给出 4 条证据，再重复写成空数组。工具参数、结构化正文及二次序列化字段统一严格拒绝重复键；移除可能吞掉重复键的 `json_repair` 结构猜测，走已有模型拒绝与修正通路。
13. **高层意图被当成完整用例**：明确区分概括规则、引用已有条件与明确断言触发条件。概括名称不要求与界面文案逐字一致；显式扩大条件适用范围或未决来源冲突仍须拒绝。
14. **同页上下文被权威审查跳过**：删除“来源位置必须至少两个”的门槛，将真实表格上下文纳入已有审查信号。一条事实的表头和正文也可进入原有权威专家；其他无治理或原文上下文信号的模块仍可跳过。正式流程中仍需先完成规划验收，才能进入该动作。
15. **动作回执被 JSON 成员顺序误排**：动作检查点升级为 v2，`begin` 使用既有事件写入返回的真实 `sequence`，保存唯一正整数 `started_sequence`；恢复同一动作保留首次序号。失败观察和 SDK 历史回放统一按该序号排序，拒绝缺序号、重复序号及旧 v1 回执。事件分配与检查点、用量保存仍在原事务内；不迁移或改写线上历史记录。
16. **可选目录被当成待办、错误索引难以修正、换问法重复抽样**：完整目录按支持状态列出索引，实际未决项单独反馈。选择校验返回请求位置、非法/重复索引和真实可选范围。支持复核身份保留实际候选事实、意图及下游问题，去除问法、旧裁决、当前路由标签和附加范围标签的噪声；补选已有范围而事实未变也不形成新请求，真实新增事实或意图变化仍可形成不同请求。
17. **正常终态留下预算 pending**：正常终态事务沿原 Run→Node 锁顺序处理未完成节点及已提前标记终态的当前节点，复用既有预算结构，将未返回请求从 `pending` 转入 `interrupted`，保持 `charged`、`reported_usage` 和用量游标不变。节点动作预算、当前顶层预算及已持久化的 map 项预算沿各自原字段处理，不改重试历史，不放宽 journal 的租约写入围栏。
18. **旧 worker 覆盖终态预算**：删除 `_mark_node_cancelled` 及 10 处取消后补写调用，统一由正常终态事务结束节点。取消或失权后回滚，读取状态时禁止自动 flush 旧脏数据；保留完整 Run 刷新，确保正常完成使用最新用量。并行任务取消后的事件写入、致命错误保存前也检查现有 claim，防止先 flush 再检查。
19. **错误工具包装反复提交**：通用 `submit_result` 提交说明从实际输出 Schema 派生顶层字段；校验反馈同时给出声明字段、收到字段及对象层级。错误的 `arguments`/`params` 包装仍被拒绝，不自动拆包装，不修改 6 轮上限或预算。

20. **设计缺口反馈未展开支持差额**：在既有修复上下文中，沿真实 `fact_design_item_ids` 展开每个缺失意图的完整支持集合，并按各条真实候选分别给出缺失引用。全批必需事实已齐不等于单条用例已完整承接意图；不自动补绑、不指定承载位置，不改变验收或额度。
21. **SDK 包装局部预算异常使协调者退出**：既有 SDK 解包边界统一保留已知执行异常类型，包含局部子树预算异常；沿用现有专业失败问题记录与协调者行动分支。全局预算与网络异常保持原分类，失败候选不进入成功缓存。

## 验证边界

原需求仍有月课消终点、升级/降级时长等需要结合适用范围核对的差异，修复不能替需求方选定答案。初步核对见 `2026-09-28-crm-workbench-source-audit.md`，其中疑似冲突不等于已经证明的逻辑矛盾。
